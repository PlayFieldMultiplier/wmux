### Fixed

- **Closing a task with an open worker pane no longer fails once with
  "Permission denied" on Windows, and no longer leaves the worktree folder
  behind.** The close stops the panes in the task's worktree and then removes
  it; a worker process still leaving the folder made git fail to delete it.
  git had already dropped its record of the worktree by then, so the second
  close that seemed to succeed only closed the task and left the half-deleted
  folder under `~/.wmux/worktrees`. The close now notices the dropped record,
  deletes the leftover folder once the process has let go, and reports
  success; a removal refused while the record still exists is tried again
  for a few seconds. (#2412)
