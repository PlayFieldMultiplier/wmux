### Fixed

- **A review bot reviews a docs change, or a change in a repository with no checks, in seconds instead of an hour.** The reviewer used to start a verify worker for every pull request. That worker reinstalled dependencies and ran the whole test suite, even for one Markdown or HTML page. In a repository with no checks at all, the merge lane then refused the result anyway. Now the reviewer reads such a change itself and records its verdict with no worker. wmux checks that the files really are docs, or that the repository really declares no checks, and the merge lane counts that verdict. Any other change still gets a verify worker. The worker is told which checks will run, and installs nothing when there are none.

### Added

- **Bots can read commits in their repository.** A bot with a repository can now read a file at any commit (`git_show`) and see what a branch changed (`git_diff`), so a reviewer can read a worker's commit as soon as it exists instead of waiting for a report. Both are read-only, protected files such as `.env` are never shown, and neither is available in a turn started by an outside guest's message.
